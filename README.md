# 지방의회 AI 비서

> 초선 기초의원이 행정사무감사에서 **무엇을 확인하고 무엇을 물을지** 준비하도록 돕는 개인 AI 의정 비서입니다.

과거 지적사항과 회의록, 서비스에 적재된 법령·조례를 찾아 근거를 설명하고, 질의서와 자료요구서 초안을 만듭니다. 의원은 원문을 확인하고 초안을 수정해 최종 질의를 결정합니다.

- **데모 체험**: 로그인 화면의 ‘로그인 없이 데모 체험’ 또는 `/demo` — 예시 답변으로 문서 작성 흐름 체험. 실제 AI 조회·계정 생성·서버 저장 없음
- **실제 서비스**: [localcouncilai.vercel.app](https://localcouncilai.vercel.app) — 가입 신청 후 관리자 승인 필요. 데모 기능은 배포 후 사용 가능
- **핵심 사용자**: 행정사무감사를 준비하는 초선 기초의원 개인
- **시범 범위**: 고양특례시의회, 건설교통위원회 중심
- **현재 단계**: 핵심 기능 구현, 실사용자 검증·평가 예정. 사용 효과는 아직 측정하지 않았습니다.

## 해결하려는 문제

행정사무감사를 준비하는 의원은 여러 해의 회의록과 결과보고서를 읽고, 소관 부서의 쟁점을 골라 질의서로 정리해야 합니다. 이 과정에서 다음 세 가지 어려움이 있다는 가설로 출발했습니다.

| 어려움 | 사용자가 필요한 도움 | 서비스의 대응 |
| --- | --- | --- |
| 맥락 파악 | 작년에 무엇을 지적했고, 같은 문제가 반복됐는지 파악 | 부서·사업별 지적사항과 이전 연도 기록 확인 |
| 근거 해석 | 긴 회의록과 조문에서 질의에 필요한 내용을 이해 | 관련 자료 검색, 쉬운 설명과 출처 제공 |
| 문서 작성 | 조사 내용을 구체적인 질문으로 정리 | 질의서·자료요구서 초안 작성 |

현재 문제 정의는 공개 회의록과 결과보고서를 분석한 가설입니다. 의원·정책지원관 인터뷰나 실제 업무 관찰로 확인한 결과는 아니며, 준비 시간과 작성 부담은 사용 테스트에서 검증해야 합니다. 조사 근거와 미검증 가설은 [Discovery](docs/02-discovery.md)에 정리했습니다.

## 제품 방향과 범위

의원 개인의 이름·소속 위원회·대화 맥락을 바탕으로 업무를 돕는 비서를 지향합니다. 첫 과제는 **행정사무감사 준비에서 질의서 초안까지 이어지는 흐름**입니다.

행정사무감사를 먼저 선택한 이유는 과거 지적사항과 회의록 등 공개 자료를 활용할 수 있고, 결과물인 질의서가 명확해 사용자 가치를 평가하기 쉽기 때문입니다. 위원회 하나에서 품질을 확인한 뒤 데이터 범위를 확대합니다.

| 현재 제공 범위 | 향후 검토 또는 제외 범위 |
| --- | --- |
| 지적사항·회의록·적재 문서에 근거한 질의 준비 | 예산서 구조화, 증감·이상치 분석 |
| 소속 위원회 중심 추천과 본인 과거 발언 검색 | 지역구 기준 추천, 다른 의회로 확대 |
| 질의서·자료요구서 초안 작성과 내려받기 | 의정활동 보고서 전용 기능 |
| 의원이 원문 확인 후 수정·확정 | 정치적 입장 제안, 질의서 자동 제출 |

## 핵심 사용자 흐름

1. **이용 준비**: 실명·아이디·비밀번호로 가입을 신청하고, 관리자 승인 후 로그인합니다. 마이페이지에서 소속 상임위원회를 선택합니다.
2. **질의 주제 발견**: AI 비서의 행감 추천 질문을 선택하거나, 관심 부서·사업을 직접 질문합니다.
3. **근거 확인**: 지적사항, 이전 연도 기록, 회의록과 본인 과거 발언을 확인하고 답변의 출처를 열어 원문을 검토합니다.
4. **초안 작성**: 질의서 또는 자료요구서 초안을 요청하고, 답변을 복사하거나 문서로 받습니다.
5. **검토와 후속 확인**: 의원이 내용을 수정·확정하고, 부족한 자료는 집행부에 별도로 요구합니다. 답변 피드백을 남기고 관심 사업 알림을 확인합니다.

**사용 예시**

> “버스정책과의 작년 행감 지적사항 중 이전에도 반복된 내용이 있어?”
> → 관련 지적사항과 회의록의 근거 확인
> → “이 내용을 바탕으로 질의서 초안을 만들어줘.”
> → “이행 여부를 확인할 자료요구서도 작성해줘.”

초안은 질의 제목·배경·질의 사항·추가 요구 자료로 구성하도록 설계했습니다. 공개된 지적사항만으로 실제 이행 여부를 단정하지 않고, 확인할 질문과 필요한 자료를 제안합니다.

## 구현된 기능

아래는 저장소 코드 기준의 구현 현황이며, 운영 환경의 데이터 적재·API 설정·정기 작업 상태에 따라 사용 가능 범위가 달라집니다.

| 기능 | 사용자 가치 | 제공 방식 |
| --- | --- | --- |
| 통합 AI 비서 | 여러 자료를 따로 찾는 부담 완화 | 질문에 따라 문서·회의록·지적사항 조회 도구 선택 |
| 행감 추천 질문 | 무엇을 물을지 모르는 첫 사용 지원 | 위원회별 지적사항의 반복 여부·조치 구분 등을 활용 |
| 출처 확인 | 답변의 근거를 사용자가 직접 검토 | 인용 번호와 근거 내용, 원문 연결 |
| 질의서·자료요구서 초안 | 조사에서 작성까지 연결 | 대화에서 요청, 복사·문서 내려받기 |
| 내 발언 찾기 | 본인의 과거 질의와 후속 질문 연결 | 가입 실명으로 의회 홈페이지의 의원별 회의록 검색 |
| 대화 기록 | 이전 질문을 이어서 준비 | 대화 저장·이름 변경·삭제, 최근 대화 맥락 반영 |
| 행감 일정·관심 사업 알림 | 준비 시점과 후속 자료 확인 | 감사 기간 D-day, 등록 키워드 관련 회의록 알림 |
| 모델 선택·진행 상황 표시 | 대기 과정과 사용 모델 확인 | 모델 선택, 검색 단계 표시, 한도 초과 시 다른 무료 모델 시도 |
| 관리자 기능 | 이용 자격과 답변 품질 관리 | 가입 승인·반려, 계정 관리, 품질 대시보드 |

## 운영 정책과 신뢰 기준

| 항목 | 현재 정책·동작 |
| --- | --- |
| 이용 자격 | 관리자가 가입 신청자의 실명을 확인하고 승인. 비활성 계정은 이용 제한 |
| 개인 데이터 | 대화는 본인 소유 여부를 확인해 접근. 조회 도구는 소속 의회 범위 적용 |
| 질문 한도 | 회원별 기본 하루 50회, 한국 시간 자정 기준. 운영 설정으로 변경 가능 |
| 관심 사업 | 키워드 최대 10개 등록. 정기 작업으로 새 회의록 확인 후 서비스 내 알림 생성 |
| 근거 부족 | 자료를 찾지 못한 경우와 자료는 있으나 인용 근거가 부족한 경우를 구분해 안내 |
| AI 장애·한도 | 오류 안내와 기록. 모델 한도 초과 시 다른 무료 모델로 재시도하며, 유료 모델은 자동 전환 대상에서 제외 |
| 최종 판단 | AI는 근거 설명과 초안 작성까지 지원. 원문 대조와 최종 사용 결정은 의원이 수행 |

**출처가 있다는 사실만으로 답변의 정확성이 보장되지는 않습니다.** 화면에는 인용 근거 수와 원문 확인 안내를 표시합니다. 존재하지 않는 인용 번호는 거절하지만, 인용 문장과 주장 사이의 의미 일치 여부를 독립적으로 검증하는 기능은 아직 없습니다.

질문·의원 프로필·최근 대화와 검색 근거가 답변 생성을 위해 외부 AI 제공자에게 전달될 수 있습니다. 실제 도입 전에는 민감 자료 입력 기준, 대화 보관·삭제 정책, 외부 AI 데이터 처리 조건을 확정하고 안내해야 합니다.

## 데이터 범위와 제약

| 데이터 | 현재 활용 방식 | 한계 |
| --- | --- | --- |
| 행감 지적사항 | 결과보고서에서 구조화한 데이터를 부서·사업·연도로 조회 | 기존 작업 기록상 건설교통위원회 2024·2025년 164건. 현재 운영 DB 적재 수는 별도 확인 필요 |
| 의회 회의록 | 고양특례시의회 홈페이지 검색 후 관련 본문 확인 | 외부 사이트의 응답 속도·검색 방식·구조 변경에 영향받음 |
| 법령·조례 | 서비스에 적재한 문서를 의미 검색 | 실시간 법령 API 미연동. 최신 시행본 여부를 원문에서 확인해야 함 |
| 지적사항 처리결과 | 공개 지적사항을 바탕으로 확인 질문·자료요구 작성 | 실제 이행 여부를 확인할 처리결과 자료가 확보되지 않음 |
| 예산·집행 | 관련 적재 문서가 있으면 검색 대상에 포함 | 지방재정 API 및 예산 전용 분석 기능 미연동 |
| 행감 일정 | 공개 회의록에서 위원회별 감사 기간 추출 | 부서별 세부 감사 날짜는 제공하지 않음 |

상세한 조회 방식과 기술적 제약은 [데이터와 구조](docs/03-data-and-architecture.md)를 참고하세요.

## 성공 지표와 검증 계획

기능 구현과 효과 검증을 구분합니다. 목표 수치는 실사용 기준선을 측정한 후 정하며, 현재 성과로 제시할 수 있는 준비 시간 단축·초안 채택률 수치는 없습니다.

| 지표 | 측정 방법 | 현재 상태 |
| --- | --- | --- |
| 준비 시간 | 부서 1곳의 질의서 초안 작성 시간을 기존 방식과 비교 | 사용 테스트 필요 |
| 초안 채택률 | 제안한 질의 포인트 중 최종 질의서에 남긴 비율 | 사용 테스트 필요 |
| 근거 오류율 | 평가 질문에 대한 답변을 원문과 대조해 인용·사실 오류 확인 | 평가 세트와 검수 필요 |
| 답변 상태 | 정상·근거 부족·결과 없음·오류 비율 | 최근 30일 관리자 대시보드 구현 |
| 응답 시간·피드백 | 모델별 응답 시간, 좋아요·싫어요와 사유 확인 | 기록·조회 기능 구현 |

다음 검증은 **실제 행감 질문과 정답 근거로 평가 세트를 만들고, 의원이 한 부서의 질의서를 준비하는 과정을 관찰하는 것**입니다. 답변불가 비율이 높으면 데이터 범위를, 초안 채택률이 낮으면 질의 제안 방식을 우선 개선합니다.

## 주요 기획 결정과 다음 단계

| 결정 | 이유 |
| --- | --- |
| 여러 기능을 동시에 만들던 초기 방향에서 행감 준비에 집중 | 하나의 업무를 결과물까지 연결하고 가치를 검증하기 위해 |
| 의원 개인을 중심으로 설계 | 위원회와 본인 과거 질의 맥락을 반영하기 위해 |
| 검색과 초안 작성을 AI 비서로 통합 | 자료 조회와 문서 작성 사이의 이동을 줄이기 위해 |
| 예산·법령 실시간 연동은 후속 과제로 구분 | 확보한 데이터로 가능한 기능과 미구현 기능을 명확히 하기 위해 |

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| v1 | 행감 추천 → 근거 확인 → 질의서·자료요구서 초안 | 핵심 기능 구현, 평가 예정 |
| v1 검증·보완 | 평가 세트, 사용자 테스트, 인용 검증, 데이터 최신성·운영 정책 점검 | 진행 필요 |
| v2 | 예산 심사 준비: 예산서 구조화, 증감·이상치 분석 | 계획 |
| v3 | 의정활동 기록을 활용한 보고서 초안 | 계획 |

기획 변경의 대안과 이유는 [의사결정 기록](docs/decisions.md)에 남겼습니다. 이후 일정과 확장 범위는 v1 검증 결과에 따라 조정합니다.
