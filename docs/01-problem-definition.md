# 01. 문제 정의

> 단계: 고객 구조 파악 · 핵심 업무 선정 — **완료** (2026-10-04, 고객 구조 2026-10-05 개정)

## 한 줄 정의

> 정치·법·재정 비전문가인 초선 기초의원은 첫해의 행정사무감사·예산 심사·의정활동 보고서에서 "무엇을 봐야 하고, 무엇을 물어야 하는지" 몰라, 집행부 자료에 끌려가거나 준비에 과도한 시간을 쓴다.

## 출발점

처음 문제의식은 "지방의원은 정치나 법 전문가가 아니어서 의정활동이 어렵다"였습니다. 방향은 맞지만, 이 문장만으로는 무엇을 만들지와 무엇으로 성공을 판단할지가 정해지지 않습니다. 그래서 **누가, 언제, 어떤 업무에서, 왜 막히는지**까지 좁혔습니다.

| 질문 | 답 |
| --- | --- |
| 누가 | 2026년 7월 임기를 시작한 초선 기초의원 개인 |
| 언제 | 임기 첫해. 11월 행정사무감사, 연말 본예산 심사, 이후 의정활동 보고서 |
| 어떤 업무 | 행정사무감사 준비 (질의 대상 선정 → 근거 수집 → 질의서 작성) |
| 왜 막히나 | 맥락 부족(과거 지적사항), 해석 부족(예산·조문), 작성 부담 |

## 고객 구조

**결정 (2026-10-05): 의회가 함께 쓰는 공용 도구가 아니라, 의원 한 명에게 붙는 개인 전속 비서관으로 만듭니다.**

| 역할 | 누구 | 이 서비스에서 필요한 것 |
| --- | --- | --- |
| 사용자이자 결정자 | 초선 기초의원 본인 | 내 위원회·내 지역에 맞춘 설명, 확인할 점, 바로 쓸 수 있는 질의서 초안 |
| 연결 승인 | 서비스 관리자 | 계정을 실제 의원과 연결할 때 본인 여부 확인 |
| 보안 검토 | 의원 본인, 필요시 의회 정보보안 담당 | 외부 AI로 나가는 데이터 범위, 대화 기록 보관 방식 |

### 왜 개인 비서인가

- **기초의원에게는 개인 보좌진이 없습니다.** 의회에 정책지원관이 있지만, 2022년 지방자치법 전부개정으로 의원 정수의 2분의 1 범위에서 둘 수 있게 된 공용 인력이라 정원을 다 채워도 1명이 의원 2명 이상을 맡습니다 ([국민참여입법센터](https://opinion.lawmaking.go.kr/gcom/nsmLmSts/out/2201201/detailRP)).
- **의정활동은 의원마다 다릅니다.** 행감은 위원회별로 소관 부서만 감사하고, 지역구 사업과 관심 분야도 의원마다 다릅니다. 공용 검색 도구는 이 차이를 매번 사용자가 설명해야 합니다.
- **비서의 가치는 맥락을 기억하는 데서 나옵니다.** 의원의 과거 발언, 준비했던 질의서, 관심 사업을 알고 있어야 "작년에 질의하신 사업이 아직 이행되지 않았습니다" 같은 도움을 줄 수 있습니다.

### 처음 가정에서 바뀐 점

처음에는 정책지원관을 실제 작업자로, 의회사무국을 도입 결정자로 보고 의회 공용 도구를 가정했습니다. 사용자와 결정자가 다르면 제품이 결정자(관리 기능, 일괄 도입)에 맞춰지기 쉽고, 의원 한 명의 맥락에 깊이 맞추기 어렵습니다. 그래서 **사용자와 결정자가 같은 의원 개인**에 맞추는 쪽을 택했습니다. 정책지원관과의 협업 기능은 이후 검토 대상으로 남깁니다.

### 설계에 미치는 영향

| 항목 | 설계 |
| --- | --- |
| 의원 프로필 | 마이페이지에서 위원회·지역구 설정. v1은 위원회 기준으로만 맞춤 |
| 실제 의원 연결 | 의원 명단에서 본인 선택 → 관리자 승인 후 연결. 다른 사람 이름으로 쓰는 것을 막음 |
| 의원 본인 활동 | 연결된 의원의 과거 발언·질의를 의회 홈페이지 의원별 회의록에서 가져옴 |
| 기억 | 관심 사업, 준비한 질의서를 의원별로 저장해 다음 대화에 반영 |
| 데이터 분리 | 지적사항·회의록·법령은 공통 데이터, 대화·기억·질의서는 의원 개인 데이터로 분리 |

## 왜 지금인가

- 2026년 6월 3일 지방선거 후 7월부터 새 임기가 시작됐습니다. 전북 사례를 보면 기초의회 당선자의 36~50%가 초선입니다 ([전북일보, 2026-06-22](https://jjan.kr/article/20260622500231)).
- 고양특례시의회는 11월 제2차 정례회에서 2026년도 행정사무감사를 엽니다. 이를 위해 9월 4~10일에 4개 상임위별로 35개 현장을 사전 점검했습니다 ([위키트리, 2026-09-02](https://www.wikitree.co.kr/articles/1156829)).

## 핵심 업무 선정

세 후보 중 하나를 먼저 끝까지 해결합니다.

| 기준 | 행정사무감사 | 예산 심사 | 의정활동 보고서 |
| --- | --- | --- | --- |
| 시기 (첫해 일정) | 가장 먼저 옴 | 그다음 | 가장 나중 |
| 비전문가가 겪는 어려움 | 큼 (무엇을 물을지 모름) | 큼 (숫자 해석) | 중간 (글쓰기) |
| 공개 데이터로 해결 가능성 | 높음 (과거 행감 회의록, 지적사항) | 중간 (예산서 구조화 필요) | 낮음 (개인 활동 데이터 필요) |
| 결과물 명확성 | 질의서 | 질의 포인트 | 보고서 |
| 다음 업무로 재사용 | 회의록·예산 도구가 예산 심사로 이어짐 | 보고서 재료가 됨 | — |

**결정: 행정사무감사 준비.** 시기가 가장 이르고, 공개 데이터로 해결할 수 있으며, 여기서 만든 도구가 예산 심사와 보고서로 그대로 이어집니다.

**v1 범위: 건설교통위원회.** 위원회 하나로 기능을 끝까지 완성한 뒤 나머지 4개 위원회(의회운영·기획행정·환경경제·문화복지)로 넓힙니다. 데이터 준비는 위원회당 몇 분이면 되므로, 범위를 좁힌 이유는 품질 확인과 평가에 집중하기 위해서입니다.

## 목표 업무 흐름

```
감사 대상 부서 선택
 → 이 부서의 작년 행감 지적사항과 이행 여부
 → 올해 예산·집행 현황에서 눈에 띄는 변화
 → 관련 조례·법령의 쉬운 설명
 → 질의 포인트 제안 (근거 포함)
 → 질의서 초안 → 의원이 수정·확정
```

## 성공 지표 (초안)

실사용자 측정 전이라 기준선은 Discovery와 첫 사용 테스트에서 정합니다.

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| 준비 시간 | 부서 1곳의 질의서 초안 완성까지 걸린 시간 | 기준선 측정 후 설정 |
| 초안 채택률 | 제안된 질의 포인트 중 의원이 질의서에 남긴 비율 | 기준선 측정 후 설정 |
| 근거 오류율 | 인용이 근거 문장과 맞지 않는 답변의 비율 (평가 세트 기준) | 법령·조례 0%에 가깝게 |
| 답변불가 비율 | 근거 부족으로 답하지 않은 비율 | 추적 (너무 높으면 데이터 부족 신호) |

## 범위 밖 (v1)

- 질의 방향이나 정치적 입장에 대한 조언
- 질의서 자동 제출 등 외부로 나가는 행동
- 예산 심사·보고서 전용 기능 (v2, v3)
- 건설교통위원회 외 다른 위원회 데이터
- 지역구 기준 우선순위 (지역구 정보는 저장만)
- 고양특례시의회 외 다른 의회 데이터
