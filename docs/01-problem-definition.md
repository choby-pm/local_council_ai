# 01. 문제 정의

> 단계: 고객 구조 파악 · 핵심 업무 선정 — **완료** (2026-10-04)

## 한 줄 정의

> 정치·법·재정 비전문가인 초선 기초의원은 첫해의 행정사무감사·예산 심사·의정활동 보고서에서 "무엇을 봐야 하고, 무엇을 물어야 하는지" 몰라, 집행부 자료에 끌려가거나 준비에 과도한 시간을 쓴다.

## 출발점

처음 문제의식은 "지방의원은 정치나 법 전문가가 아니어서 의정활동이 어렵다"였습니다. 방향은 맞지만, 이 문장만으로는 무엇을 만들지와 무엇으로 성공을 판단할지가 정해지지 않습니다. 그래서 **누가, 언제, 어떤 업무에서, 왜 막히는지**까지 좁혔습니다.

| 질문 | 답 |
| --- | --- |
| 누가 | 2026년 7월 임기를 시작한 초선 기초의원 (그리고 이들을 보좌하는 정책지원관) |
| 언제 | 임기 첫해. 11월 행정사무감사, 연말 본예산 심사, 이후 의정활동 보고서 |
| 어떤 업무 | 행정사무감사 준비 (질의 대상 선정 → 근거 수집 → 질의서 작성) |
| 왜 막히나 | 맥락 부족(과거 지적사항), 해석 부족(예산·조문), 작성 부담 |

## 고객 구조

| 역할 | 누구 | 이 서비스에서 필요한 것 |
| --- | --- | --- |
| 주 사용자 | 초선 기초의원 | 쉬운 설명, 확인할 점, 바로 쓸 수 있는 질의서 초안 |
| 실제 작업자 | 정책지원관 | 자료 수집·분석 시간 단축, 여러 의원의 요청 동시 처리 |
| 도입 결정 | 의회사무국·의장단 | 비용, 효과의 근거, 운영 부담 |
| 보안 검토 | 정보보안·개인정보 담당 | 외부 AI로 나가는 데이터 범위, 로그, 공공 클라우드 기준 |

정책지원관은 2022년 지방자치법 전부개정으로 의원 정수의 2분의 1 범위에서 둘 수 있게 됐고, 업무에 행정사무감사 지원과 시정 질의서 작성 지원이 포함됩니다 ([국민참여입법센터](https://opinion.lawmaking.go.kr/gcom/nsmLmSts/out/2201201/detailRP)). 정원을 다 채워도 1명이 의원 2명 이상을 맡으므로, 지원관의 시간을 줄이는 도구는 여러 의원에게 함께 효과를 냅니다.

**설계에 미치는 영향**: 화면과 문구는 의원이 바로 이해할 수 있게 쉽게 만들고, 작업 흐름은 지원관이 여러 의원의 요청을 처리할 수 있게 설계합니다. 보안 검토자를 위해 외부 모델로 보내는 데이터 범위를 문서로 명시합니다.

## 왜 지금인가

- 2026년 6월 3일 지방선거 후 7월부터 새 임기가 시작됐습니다. 전북 사례를 보면 기초의회 당선자의 36~50%가 초선입니다 ([전북일보, 2026-06-22](https://jjan.kr/article/20260622500231)).
- 고양특례시의회는 11월 제2차 정례회에서 2026년도 행정사무감사를 엽니다. 이를 위해 9월 4~10일에 4개 상임위별로 35개 현장을 사전 점검했습니다 ([위키트리, 2026-09-02](https://www.wikitree.co.kr/articles/1156829)).

## 핵심 업무 선정

세 후보 중 하나를 먼저 끝까지 해결합니다.

| 기준 | 행정사무감사 | 예산 심사 | 의정활동 보고서 |
| --- | --- | --- | --- |
| 시기 (첫해 일정) | 가장 먼저 옴 | 그다음 | 가장 나중 |
| 비전문가가 겪는 어려움 | 큼 (무엇을 물을지 모름) | 큼 (숫자 해석) | 중간 (글쓰기) |
| 공개 데이터로 해결 가능성 | 높음 (과거 행감 회의록, 지적사항) | 중간 (예산서 구조화 필요) | 낮음 (개인 활동 데이터 필요) |
| 결과물 명확성 | 질의서 | 질의 포인트 | 보고서 |
| 다음 업무로 재사용 | 회의록·예산 도구가 예산 심사로 이어짐 | 보고서 재료가 됨 | — |

**결정: 행정사무감사 준비.** 시기가 가장 이르고, 공개 데이터로 해결할 수 있으며, 여기서 만든 도구가 예산 심사와 보고서로 그대로 이어집니다.

## 목표 업무 흐름

```
감사 대상 부서 선택
 → 이 부서의 작년 행감 지적사항과 이행 여부
 → 올해 예산·집행 현황에서 눈에 띄는 변화
 → 관련 조례·법령의 쉬운 설명
 → 질의 포인트 제안 (근거 포함)
 → 질의서 초안 → 의원이 수정·확정
```

## 성공 지표 (초안)

실사용자 측정 전이라 기준선은 Discovery와 첫 사용 테스트에서 정합니다.

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| 준비 시간 | 부서 1곳의 질의서 초안 완성까지 걸린 시간 | 기준선 측정 후 설정 |
| 초안 채택률 | 제안된 질의 포인트 중 의원이 질의서에 남긴 비율 | 기준선 측정 후 설정 |
| 근거 오류율 | 인용이 근거 문장과 맞지 않는 답변의 비율 (평가 세트 기준) | 법령·조례 0%에 가깝게 |
| 답변불가 비율 | 근거 부족으로 답하지 않은 비율 | 추적 (너무 높으면 데이터 부족 신호) |

## 범위 밖 (v1)

- 질의 방향이나 정치적 입장에 대한 조언
- 질의서 자동 제출 등 외부로 나가는 행동
- 예산 심사·보고서 전용 기능 (v2, v3)
- 고양특례시의회 외 다른 의회 데이터
