# 실제 AI 데모와 사용 한도

2026-10-23. 로그인 화면의 데모 버튼과 `/demo`에서 실제 Gemini 3.6 Flash에 질문할 수 있다. 기존의 정해진 예시 답변은 제거했다.

## 사용 범위

- 정식 비서와 같은 `runCouncilAgent`로 공개 행감 지적사항·고양시의회 회의록·공식 법령을 조회하고 초안을 만든다. 법제처 인증이 없으면 해당 조회의 미설정을 표시한다.
- 데모는 체험용 고정 의회·위원회 프로필을 사용한다. 실제 의원 계정이나 대화와 연결하지 않는다.
- 개인 발언 검색과 적재 보조 문서 검색은 비활성화한다. 공개 지적사항·공식 원문 조회만 허용한다.
- 최근 3턴을 전달해 후속 질문을 이어간다. 질문·답변·대화는 서비스 DB에 저장하지 않으며 새로고침하면 화면 대화가 초기화된다. 사용량 한도는 초기화되지 않는다.
- 질문과 최근 대화는 Google AI로 전달된다. 화면에서 이를 안내하고 민감 자료 입력을 피하도록 한다.

## 서버에서 적용하는 제한

| 항목 | 제한 |
| --- | --- |
| 동일 IP | 한국 날짜 기준 하루 10회 |
| 전체 공개 데모 | 한국 날짜 기준 하루 100회 |
| 요청 간격 | 동일 IP에서 최소 15초 |
| 질문 | 1,000자 |
| 대화 맥락 | 최대 6개 메시지, 각 2,000자 |
| 요청 본문 | 64,000바이트 |
| AI 실행 | 최대 4단계, 단계별 출력 최대 2,000토큰, 총 60초 |
| 모델 | Gemini 3.6 Flash 고정, 자동 모델 전환·자동 재시도 없음 |

`demo_question_usage`에 하루별 전체 카운터와 해시된 IP 카운터를 저장한다. IP 원문이나 대화 내용은 저장하지 않는다. Vercel이 덮어쓰는 `x-forwarded-for`로 식별하며, 운영 환경에서 유효한 IP를 확인하지 못하면 AI를 호출하지 않는다. 로컬 개발은 루프백 IP 하나로 취급한다. 다른 프록시로 이전할 때는 신뢰하는 헤더를 다시 검토해야 한다.

두 카운터를 하나의 SQL 문장에서 예약한다. 어느 한도든 초과하거나 간격이 짧으면 전체 예약을 롤백하므로 거절된 요청이 전체 카운터를 소모하지 않는다. 예약 후 AI가 실패한 요청은 횟수에 포함된다. 한도·DB 확인 실패·AI 장애에서는 고정 예시로 대체하지 않고 오류를 표시한다.

IP 기반 제한이므로 같은 네트워크의 사용자는 횟수를 공유하고, IP를 바꿀 수 있는 사용자를 개인별로 식별하지 못한다. 전체 하루 100회 상한이 있어 IP 변경으로 전체 AI 호출량이 무제한 늘어나지는 않는다. 모델 제공자의 실제 사용량 정책과 과금 조건은 별개다.

## 검증

- 회귀 검사: 입력 길이·대화 역할·헤더 기반 식별·실제 계정 API 분리·예약 SQL·한도 초과 처리.
- 실제 PostgreSQL: 여러 요청을 동시에 보내 전체 상한·개별 상한·간격을 넘지 않는지 확인. 거절된 요청의 전체 카운터 롤백과 한국 날짜별 분리를 검증.
- 로컬 HTTP 실호출: 로그인 없이 공개 지적사항을 질문해 실제 AI 답변·출처 3건 확인. 대화 맥락을 이용한 자료요구서 초안·출처 1건 확인. 즉시 반복 요청은 AI 호출 전 429 응답 확인.
- Gemini 2.5 Flash는 이 키에서 신규 사용 불가, 3.8 Flash는 일시 과부하로 확인되어 실제 정상 응답을 확인한 기존 기본 계열인 3.6 Flash를 선택했다. 모델 가용성은 운영 중 달라질 수 있다.
