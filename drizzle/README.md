# 일일 사용량 마이그레이션

기존 `src/db/schema.ts`의 테이블이 설치된 DB를 전제로 한다. `0000`은 `daily_question_usage`를 추가하고 현재 한국 날짜의 기존 질문 수를 옮긴다. `0001`은 공개 AI 데모의 전체·IP별 한도를 계산할 `demo_question_usage`를 추가한다. 기존 테이블을 생성하는 초기 설치용 마이그레이션은 아니다.

`meta/0000_snapshot.json`은 기존 테이블을 포함한 전체 스키마 기준점이다. 이 저장소는 앞서 Drizzle push로 관리하던 기존 스키마가 있어, 첫 증분 SQL에는 새 테이블만 포함했다. 이후 generate는 전체 schema.ts를 기준으로 실행한다.

배포 순서:

1. 운영 DB의 격리 브랜치를 만들고 직접 연결 문자열을 준비한다. 운영 계정·대화로 테스트하지 않는다.
2. 기존 timestamp가 UTC로 저장되었는지 확인한다. backfill은 이 전제를 사용하며 다른 시간대로 저장했다면 변환을 조정한다.
3. 직접 연결 URL을 `DATABASE_URL_UNPOOLED`로 설정한 환경에서 `npx drizzle-kit migrate`로 적용한다. 필요하면 설치된 dotenv-cli로 별도 테스트 환경 파일을 로드한다.
4. 회원별 질문 50개 제한을 동시 요청으로 확인한다. 한도 후 대화를 삭제해도 사용량이 줄지 않는지, KST 자정 이후 새 날짜로 집계되는지 확인한다.
5. 검증 후 기존 앱의 질문 접수를 잠시 중지한 상태에서 운영 마이그레이션을 적용하고 새 코드를 배포한다. backfill과 앱 교체 사이에 예전 코드로 접수한 질문은 별도 집계되지 않는다.

2026-10-23 기준 `0000`·`0001` 운영 적용을 완료했다. 별도 테스트 스키마에서 backfill·동시 요청 상한·거절 시 롤백·한국 날짜 분리를 검증했으며 테스트 스키마는 제거했다. Neon 브랜치 테스트는 수행하지 않았다. 다른 환경에서도 앱 배포 전에 마이그레이션이 선행되어야 한다.

로컬 회귀 검사는 `npm run test:chat`이다. 외부 응답을 모의 처리하며 실제 PostgreSQL 동시성·마이그레이션 검사를 대신하지 않는다.
